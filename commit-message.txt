Fix the packaged AI worker launch and stop the guide covering the splash

- AI (exe): the worker log was opened under the bundle root before the worker
  started, so a real install failed with PermissionError and AI Voice fell back to
  Original. It now goes to the writable data directory beside the app log, which is
  also where the reader is told to collect logs from.
- AI (exe): the worker was launched with the unpacked bundle as its working
  directory, where only the GUI's frozen src/gui exists, so it exited with
  "No module named 'src.vc'" before loading anything. It now runs from the install
  folder -- the same folder the project's own tools use -- which is also where
  src.vc.service, the models and the environment live. Naming that folder on
  PYTHONPATH instead would let directories such as tools/psutil shadow the
  environment's own packages.
- GUI: the first-run guide is a window of its own, so the splash overlay could not
  cover it: opened 400 ms in, it appeared on top of the animation. It now waits for
  the splash to reveal the window, and opens immediately when no splash plays.
- Tests: the packaged launch is covered without a build (log location, working
  directory, module invocation) and the guide timing is driven end to end. The
  existing device test now isolates the log directory it no longer shares with the
  repository root.
